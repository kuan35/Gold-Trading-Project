## 啟動

需要 Python 3.11+、Node.js 20.19+ 或 22.12+、npm。以下在此 README 所在的產品資料夾執行；原研究工作區則先 `cd product`。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
cd ..
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8765
```

瀏覽 http://127.0.0.1:8765。無 private 資料時，自動載入標示清楚的合成行情與合成案例；不是原交易員績效。已安裝依賴並完成建置後，也可用 `powershell -File start.ps1` 在背景啟動本機伺服器。

開發前端可另開終端執行 `cd frontend`、`npm run dev`，使用 http://127.0.0.1:5173。Vite 將 API 轉送 8765，後端仍需啟動。

## 模擬規格與邊界

單一記憶體工作階段，重設或重啟會清空模擬持倉。每手 100 盎司、USD、本機初始餘額 10,000、固定 0.30 價差；未模擬佣金、隔夜費、保證金或強制平倉。未設定停損時，價格情境不是損失上限。同棒觸及停損與停利採停損優先。不是券商逐筆成交重建。

本機歷史檢索先篩方向與已成熟時間，再以收盤路徑和技術指標的同層相對排名排序，前 15 個不同操作群內依固定文字型態重排；手數、首筆／加倉與盈虧不參與排名。每個操作群最多一筆；足夠相似門檻尚未完成盲評校準。未知時區案例以全群最晚平倉加 14 小時及 1 分鐘作保守成熟界線。這不是已確認時區或已證明帳戶完整。詳細方法與驗證界線見 `docs/market_state_text_retrieval_20261019.md`。

歷史獲利比例僅描述匹配池，不是目前下單的預測機率。合成案例、回放模擬與交易員紀錄分別標示。可選外部 LLM 只負責解釋，沒有確認成交的權限。

## cTrader DEMO 連線診斷（本機）

已準備受 Git 忽略的 `product/.env.ctrader`，可參照 `product/ctrader.env.example`。到 cTrader Open API Applications 的 **Credentials** 複製 Client ID 與 Client Secret，填在 `CTRADER_CLIENT_ID`、`CTRADER_CLIENT_SECRET` 等號後。若要進一步驗證帳戶，須先用該應用的 Sandbox/Playground 完成 OAuth，將 Access Token 填在 `CTRADER_ACCESS_TOKEN`；唯讀檢查建議選 `accounts` 權限。若 token 具有交易權限，診斷也只送查詢及授權訊息，會明確回報權限範圍。不要把任何值貼進聊天或提交到 Git。多個 DEMO 帳戶時可選填 `CTRADER_ACCOUNT_ID`；不填會測第一個獲授權的 DEMO 帳戶。這不是單一 API key。

```powershell
cd product
.\.venv\Scripts\python.exe -m pip install -r requirements-ctrader.txt
.\.venv\Scripts\python.exe scripts/check_ctrader_demo.py
```

診斷只連 `demo.ctraderapi.com`，依序測 TLS、應用授權，若有 token 再測 DEMO 帳戶授權和可交易商品清單；輸出不含金鑰、token 或帳戶 ID，程式不會送出委託。此工具尚未接入產品的下單模式；網站仍維持未連線，直到另行完成報價、草稿確認、重查與券商回報流程。應用 Active 不等於帳戶已授權。
