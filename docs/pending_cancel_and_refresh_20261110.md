# 取消已送掛單、過期續單與報酬顯示

本機新版：`http://127.0.0.1:8766/`。本次仍是 DEMO 寫入、LIVE 唯讀；未執行任何實際送單、平倉或取消驗收。

## 取消送出後的委託

右側「帳戶 → 待成交」每筆卡片有「取消掛單」。這與下單表單的清除準備中草稿不同。

1. 顯示原訂單編號、方向、剩餘掛單資訊及價位。
2. 後端建立取消確認草稿，不立即操作券商。
3. 使用者按「確認取消掛單」，後端再核對同帳戶、原訂單身分及最新待成交狀態，使用獨立防重送key送取消請求。
4. 明確取消回報後等待帳戶清單更新；UNKNOWN保留同一請求查詢，不重送。

支援既有進場與平倉 LIMIT／STOP／STOP_LIMIT 掛單；取消進場掛單不需要先有持倉。只取消未成交剩餘部分，不平掉已成交部分。如果已成交，必須看持倉區，不能宣稱取消成功。官方以 `ProtoOACancelOrderReq` 取消原 `orderId`，成功為 `ORDER_CANCELLED`。[cTrader Open API](https://help.ctrader.com/open-api/messages/#protooacancelorderreq)。

確認時比較原單方向、數量、單型、進出場意圖、綁定部位、限價、觸發價、SLTP及成交量指紋。服務重啟後，若取消請求沒有回報，只能以 CURRENT 同帳戶、同原單身分的明確券商歷史終態核對：CANCELLED解除為已取消，FILLED／EXPIRED／REJECTED表示未能取消。不能靠待成交列消失或原單client ID猜成功。

## 已檢查草稿不因30秒期限卡住

保留後端原有新鮮度檢查；畫面不再把過期草稿的主要操作永久停用。

- 到期後顯示「更新報價並繼續」，沿用同一份填寫內容重新取得盤面、帳戶及風險。
- 成功後對照前後參考價、總手數、停損情境損失，使用者再確認送出。原單已提交或回報未明不能用更新繞過防重送。
- 更新失敗保留原欄位及核對區，可重試；不將舊報價當成最新。
- 刷新只重跑程式檢核與固定快照，不重跑付費Agent。原聊天仍是原快照分析，畫面說明此差別。
- 點確認時若剛好跨過期限、報價變動，或服務重啟使草稿遺失，明確未送出的錯誤可轉更新流程；回報不明仍查原請求。

## 持倉與紀錄報酬

持倉主顯「浮動淨損益 ÷ 券商目前占用保證金」，由 `ProtoOAPosition.usedMargin` 與自身 `moneyDigits` 還原保證金。分母是目前占用，不是最初投入；券商浮動淨損益仍不含潛在平倉佣金。若券商未提供，USD帳戶可顯示明確標註的槓桿估計；已知零或無效分母不冒算。[官方 Position 定義](https://github.com/spotware/openapi-proto-messages/blob/main/OpenApiModelMessages.proto)。

價格報酬率收在「報酬率依據」詳情。券商歷史平倉成交可用實際入場均價與成交價顯示方向調整價格報酬；缺歷史實際保證金時不稱保證金ROI。

新增下單前「帳戶淨值歸零情境」，計算條件及限制見 [帳戶情境與報酬公式](account_scenarios_20261110.md)。這是固定持倉、固定價差、忽略停損與強平的估算；券商可能先強平，不能作精確強平價。非USD／不完整持倉／行情或損益過期時不顯示推測價位。

## Agent盤面與案例整合

新增固定格式的雙週期事前盤面描述，並保留原單進出場與事後結果分離；同份Agent請求同時取得目前盤面、案例型態、全池統計及個案操作。BUY草稿與偏空盤面要分開說；有案例時須解釋支持與反證，不只列技術面。見 [案例證據格式](market_case_agent_evidence_20261110.md)。三段形態是描述，不新增檢索門檻，也不是以獲利反推型態。
