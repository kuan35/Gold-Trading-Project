# 白話交易計畫與歷史操作摘要

2026-11-09。沿用現有 React／FastAPI、模型選擇、案例索引與人工送單流程。

## 使用者先看到什麼

1. **綜合建議**：主要方向、最重要原因、可以嘗試的進場條件，以及失效／停損和停利參考。約80–150字，不堆各週期指標，不先報組數。
2. **歷史操作參照**：第一筆相似原單的日期、方向、進出價及平倉日期、原單價格報酬；有報表損益時才加金額及實際幣別。Agent說明相同處與差異，不把交易結果冒充交易員當初動機。
3. **按需展開**：更多案例、固定30分鐘多空試算、完整統計、原始時鐘與規則依據。

若模型未把原單數值寫進摘要，介面另外呈現同一份已驗證證據的簡短操作資料，避免使用者明明找到案例卻看不到日期與報酬。若模型已完整敘述則不重複資料列。

## 原因與調整

先前模型被要求整段引用structure，容易把時間戳、均線、價格關係完整貼出。現在傳簡短的現價相對均價與已收棒判讀，完整數值仍可透過引用標記取用。

先前直接把程式WAIT和樣本數理由交給模型，容易形成「有方向卻只重複等待」。現在模型取得盤面事件、個別案例及具體風險狀態，提出自己的條件式交易計畫。超出風險預算、歷史原單虧損反證、成本問題及方向衝突依然明確提供。程式原action、reason與數值保留在API和詳細依據，沒有改研究規則或送單檢核。

進出價只用當前快照的有效支壓、草稿與方向相符的保護價。歷史絕對價格不能直接拿來當現在的買賣目標；方向相反的停損停利也不能混用。缺價位就說訊號條件，不編數字。模型無送單權限。

## 用詞

|舊稱|對使用者的說法|
|---|---|
|Bid／Ask|目前可賣出價／目前可買進價|
|五分K MA20／MA60|最近100分鐘均價／最近5小時均價|
|十五分K MA20／MA60|最近5小時均價／最近15小時均價|
|一小時K MA20／MA60|最近20小時均價／最近60小時均價|
|保證金ROI|保證金報酬率|

「20期」指20根該週期K棒，不是20分鐘。上述時間是20／60根棒代表的交易時間，若跨休市或缺棒，日曆跨度可能更長。這是收盤價的算術平均，不是逐tick按時間加權的平均成交價。

## 最低案例數（2026-11-10修訂）

依使用者2026-11-10要求，`backend/trade_advice.py` 的 `MIN_SAMPLES` 從10改為1，有1組完整資料即可進入歷史多空比較及建議檢查。一個去重後的歷史盤面，需要完整後續30分鐘，才能用同一觀察區間、各自交易成本同時試算做多及做空，這才是一組完整配對。它不同於畫面最多顯示五筆，也不等於實際訂單數；候選群不保證都是完全獨立的交易決策。

摘要後方由程式標示本次相似案例總數，不使用已顯示列數或可比較觀察列代替。多空試算的去重盤面池與本方向案例池可能不同，數量不同時分開標示，不說成其中幾組；缺值不補0。成本、原單虧損反證、事件方向、風險預算與人工確認仍檢查。只有0組完整配對時，程式才因最低樣本數不足回等待；Agent仍可依當前有效盤面擬條件式計畫，不能把個案結果當成這次獲利機率。這是產品使用門檻修改，不代表已證明統計可靠性或收益改善。
