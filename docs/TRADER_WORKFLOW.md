# 交易員工作流程：計畫、風險與提醒

這些功能在下載後的本機版使用。GitHub Pages 只有靜態展示，不提供私人紀錄、券商監控或帳戶下單。

## 操作方式

1. 在交易對話提問；先看到回答與支持／相反依據，案例與未通過統計再按需展開。
2. 右側填寫方向、單型、停損停利。原有USD、價格報酬率、預估保證金ROI保留；新增「本筆停損占淨值」與「風險：預期獲利」。展開可查看黃金合計情境風險。
3. 可在「依可承擔風險反算手數」自行填USD或淨值比例，先計算，再按「以最新報價重算並套用手數」。計算不需要先填手數，也不會直接建立委託。手數按券商級距向下取整；低於最小手數就拒絕，不強補。
4. 選填「這筆交易的理由」後檢查委託。系統同時保存交易計畫：原始理由、草稿、當時分析與查詢／案例圖表。空白理由使用最近一次討論問題。仍需原本的人工確認才送DEMO單。
5. 上方「計畫」或右側「紀錄 → 交易計畫」可查看原始證據、券商回報及填寫事後復盤。刪除聊天不會刪除此計畫；原理由與分析不被復盤覆寫。回顧模型只在按下回顧時使用目前選定的助手，沿用當時固定依據。
6. 在右側「即時圖」，有效草稿會顯示擬進場、停損、停利及紅綠情境區。拖曳標籤或鍵盤上下鍵只更改草稿欄位；舊的委託確認會失效，須重新檢查。市價進場線唯讀；限價進場線可調。歷史案例圖不會被改成目前草稿。
7. 上方「提醒」可建立即時Bid/Ask價位、已收五分棒Bid價位，或官方事件提前提醒。建立官方事件前可按「更新官方事件」。一輪觸發一次；可暫停、重新啟用或刪除。通知可回到提醒／原對話。

## 數字的意義

- 本筆停損USD＝方向調整後的擬進場到停損距離 × 合約盎司。停損淨值比例以正的USD帳戶淨值計。
- 盈虧比使用本筆停利情境獲利÷停損情境損失，不是相似案例勝率。
- 合計僅涵蓋黃金持倉、待成交開倉單與本筆。既有持倉按當前可平倉Bid/Ask至SL的額外不利變動計；掛單按指定進場至SL計。不多空互抵，待平倉單尚未成交前不減風險。
- 任一應計部位缺有效SL或資料過期，合計顯示未知，不把缺值當零。費用、滑價、跳空未納入，數字不是最大損失保證。
- USD反算需要有效新報價與合約規格；淨值比例另需10秒內的帳戶與PnL、USD正淨值。報價有效期5秒。
- 唯讀試算與提醒允許來源時鐘最多快於本機0.25秒，處理實測約0.1秒的券商時鐘差；超過仍拒用。這沒有放寬券商草稿或確認送單的檢查。
- 保證金ROI沿用券商預估／個人槓桿假設；與停損占淨值是不同分母。沒有把現在的槓桿套回歷史案例。
- 券商已接受不等於成交；已觀察到部分平倉也不推定整筆全平。共用部位不能可靠分攤單筆淨ROI時仍標未知。

## 保存與監控界線

- `private/trade_plans.sqlite`：本人帳戶的交易計畫與固定證據。
- `private/trade_alerts.sqlite`：本人帳戶的提醒及觸發事件。
- 檔案均不在發布白名單，不能把作者的紀錄、憑證或AI登入傳給同學。每人使用自己的DEMO。
- 提醒需本機後端持續運行且資料新鮮。停止、斷線、換帳戶或長缺口後先建立新基準，不回補離線期間是否曾碰價；沒有通知不代表條件沒有發生。頁面關閉時事件可在服務內保存，重新開啟只通知最近10分鐘內的新事件。
- 官方事件是建立時有效的官方排程，不是實際發布值；排程可能更動，請確認最新官方資料。已過提醒時間不能重新啟用舊事件，須另選未來事件。
- 提醒、風險計算與圖上操作沒有自動下單或自動呼叫模型權限。LIVE仍為原有唯讀範圍。
- 新功能沒有更動相似規則／門檻；通過試驗條件不代表獲利機率或人工相似準確率。

## 開發驗證

後端測試包含Decimal級距、過期／非USD、帳戶隔離、固定證據、復盤版本衝突與提醒持久化去重。瀏覽器使用合成帳戶攔截變更API驗證反算、拖曳、舊確認失效、復盤重整及通知去重；沒有實際送單或消耗模型額度。
