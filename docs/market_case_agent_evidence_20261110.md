# 盤面、歷史形態與原單結果的同快照證據

2026-11-10。本機動態分析補齊案例敘事證據，不變更檢索條件、排序、相似容忍或送單權限；公開 Pages 的靜態索引沒有因此升級。

`backend/market_case_brief.py` 只讀已選案例的進場前 OHLC 與既有規則事件／末段標籤。`prepare_analysis` 將查詢盤面及最多五個已展示案例各自固定描述成：

- 既有固定區間事件、末半小時方向；未提供既有標籤時保持未知。
- 五分鐘最後60根，固定拆20／20／20根；一小時最後20根，拆7／7／6根。各窗口與各段以首開至末收計算百分比，Decimal計算，方向只按正、負、零分為上行／下行／持平，沒有新增相似門檻。
- 兩個週期各段方向相同或不同，配合同編號 `history.caseN` 的既有定量差距供 Agent 比較支持與反證。三段方向相同不代表完整路徑相同或訊號已確認。

只使用在各自參考截止時已收的棒；形成中或截止後的棒不入描述。完整根數不足、OHLC無效、時序重複／逆序、參考時點晚於查詢時點等情況，形態顯示資料不足，不補零、不從盈虧猜形態。這個描述器不讀原單平倉價、損益或帳戶，也不把事後結果寫回檢索特徵。歷史參考仍為 `PROJECT_REFERENCE`，原始券商時鐘仍為 `UNKNOWN`。

新增事實 ID 是 `history.query_shape`、`history.shapeN`、`history.shape_comparisonN`，N為本次展示順序。原單進出與結果另用 `history.tradeN`，由原先前兩例擴為最多五例，仍須有合法原單資料及查詢前已成熟的 `available_at`；不能因形態存在就捏造缺少的原單資料。`history.aggregate` 仍是全部通過且去重池的代表原單統計，不改用畫面前五例當母體。問停損／後續時也保留同快照的進場前形態與原案例事實，避免只剩事後結果。

`draft.terms` 保存同份草稿已填方向、單型、手數、限價及SLTP。即使缺券商合約資料導致風險不能試算，已填欄位也不消失。無法解析的數值明示已填但無效，不冒充未填。`draft.risk` 在風險可試算時也明示方向、單型與實際SLTP。草稿方向與盤面偏向分開：做多草稿遇到偏空盤面應說衝突，不能改稱草稿做空；缺少程式建議保護價不等於草稿未填SLTP。

Agent 的摘要提示要求把當時盤面、歷史形態、全池結果一起解釋；有全池結果的固定草稿摘要至少引用一個同池整體數字，交代支持與反證。歷史全部獲利不是本次勝率，也不能用原單獲利倒推事前看多。進場／失效／停利只能用同快照草稿、可用建議價位或有效當前轉折，不能把歷史絕對價格搬成新單目標。

外部 writer 仍只收到占位符與白名單定性判讀，私人案例 ID、帳戶、原始價格、日期及損益數值不直接傳模型；精確值在本機填回。新增草稿方向守衛會拒絕直接把已知BUY草稿說成偏空／做空的段落，但這是窄語句檢查，不宣稱能驗證所有模型語義或保證模型敘事品質。

驗證使用合成 OHLC、原單、模型 mock，不呼叫外部模型或券商。新增回歸涵蓋事後盈虧不影響形態、截止與形成中棒、未知／無效資料、參考晚於查詢、不同方向草稿、SLTP已填但不能試算、完整同快照payload、占位符隱私與五例原單可用性；相關後端測試與既有API／統計／案例測試一併執行。實際模型敘事及交易績效尚無新增實證。

## 同日修正：草稿核對500與摘要關聯契約

實際核對委託在至少三個展示案例時發生500。根因是第3至5例的可信程式模板「通過條件不等於完全相同或下次獲利機率」，被原先共用的模型自由文字守衛當成機率宣稱；無LLM的固定快照也因此中斷。此前只用一至兩例的API fixture沒有觸發這個分支。

程式證據改走 `render_program_sections`：只從可信fact ID取得原程式模板並填值，忽略輸入section的自由文字，並標 `source=program`。模型文字仍走原數字、引用、機率及指標守衛；模型段落被拒後只能以對應程式fact模板補資料，不會回顯被拒的模型句子。沒有整體放寬市場數字或本次勝率規則。固定快照、模型全拒及程式補充均不再把這類否定模板當作預測而崩潰。

外部模型只呼叫一次。catalog新增 `summary_contract`，明定模型首段須同時使用當時盤面判讀token、同匹配池的一項整體數字與正確有效分母token、案例事件／形態token，並用支持或反證連到計畫。輸出另附 `summary_evidence_state` 與 `summary_evidence_missing`：

- `COMPLETE`：通過上述首段結構檢查；若原首段缺欄、後面已有通過數值／引用檢查的模型歷史段落，可將模型原句提升合併到首段，聯集其fact IDs，不新增連接詞或替模型杜撰判斷。
- `INCOMPLETE_HISTORY`：模型仍有可用文字，但首段未完整連接歷史。保留模型首段，末端獨立附 `source=program` 的同快照全池統計，明說模型未完成關聯；不把程式文字算為模型已完整解釋。`llm_status` 為 `partial_grounding`。
- `MODEL_REJECTED`：模型全部未通過既有grounding，返回 `source=program` 的程式證據，並附受控 `grounding_failure_code`；不把程式WAIT或程式資料當作模型建議。
- `NOT_REQUIRED`／`NOT_CHECKED`：本次無全池摘要契約，或本次沒有執行模型首段檢查。

前端穩定取 `sections.find(section => section.source === 'model')` 作同一份模型摘要；若不存在，就沒有可顯示的Agent建議。`COMPLETE`只是證據結構及引用完整，不代表支持／反證的語義一定正確，更不是相似準確率或交易績效驗證。

新增完整合成fixture包含六個全池代表原單、五個展示案例、原單結果、雙週期形態及草稿；歷史獲利比例100%、平均價格報酬0.1537%均由合成原單計算。回歸先確認POST核對回非JSON500，再驗證回JSON200；同時覆蓋模型首段完整、原句提升、漏歷史、缺正確分母、全拒回退與可信模板不得回顯自由模型文字。沒有用這些合成結果宣稱真實案例成效。
