# 同一快照的盤面與案例解釋（2026-10-22，本機）

本輪把既有情境規則、即時助手與 DEMO 草稿接成同一份分析。沒有改動 `context_contract_v1` 的成熟界線、事件、容忍或排名；LLM 解釋程式結果，不重新決定哪些案例通過。

## 使用方式

1. 開啟 http://127.0.0.1:8765/，選「對話助手 → 即時 cTrader 盤面」。
2. 保留「同時檢索歷史案例」，指定 BUY 或 SELL。這是案例比較方向，不會修改委託表單方向。
3. 啟用 Groq 才外送去識別化事實。可問「這個盤面有符合的歷史案例嗎？像在哪、差異在哪？」。
4. 每次提問只取得一次串流快照，同一批已收棒用於檢索與解釋；報價時間與已收棒截止分開顯示。
5. 有符合案例時，展開最多五組的「實際差距／試驗容忍」表，按「對照同一快照 K 線」查看五分鐘60根及一小時20根。可切換案例；每邊顯示自身價位尺度，不把圖片高度當成數值距離。
6. DEMO「檢查委託」後，在確認視窗按「解釋此草稿的盤面與案例」。它只讀建立時原分析，行情推進亦不重新檢索；解釋不延長草稿期限，不代替使用者確認。

記憶體最多保存32份快照、20分鐘。過期、被釋放或服務重啟後回傳409，不改用新盤面。原快照報價未通過有效性檢查時，明示「草稿建立時」缺行情，不把恢復後的新報價填回舊草稿。唯讀解讀容許券商時間領先本機最多100毫秒，處理實測20–30毫秒誤差；超過5秒的舊報價仍拒絕，領先時間若跨入下一個五分鐘收棒邊界亦拒絕。未放寬券商委託確認檢查。

## 程式與模型分工

`case_context.py` 轉換既有檢索結果，不排名。PASSED須原始距離、容忍、欄位與通過旗標一致；缺值、非有限值或矛盾結果降為資料不足，不補零。模型最多解釋前兩組，程序展示最多五組。

外部事實不含帳號、餘額、持倉、原始案例ID、操作群ID、逐筆損益或原始成交時間；模型仍接收使用者問題、資料來源與查詢快照時間。模型只見白名單事實及數值占位符，由程式填回數值；未知引用、裸數字及部分不允許宣稱會被拒絕，不合格段落以程式說明補充。這不是完整語意驗證，模型仍可能冗長、重複或用詞不精確。未新增送單工具。

|狀態|意義|
|---|---|
|PASSED|符合目前試驗條件，仍列出實際差距|
|NO_RULE_MATCH|有資料但全部未通過，不補近鄰|
|NO_COMPARABLE_CASES|沒有同方向、成熟且窗口不重疊的合格池|
|UNCERTAIN_EVENT|收盤接近邊界，事件尚不明確|
|INSUFFICIENT_DATA|所需盤面或索引不足，不代表全部案例不像|

未通過原因按觀察列計數，一列可違反多條，不能相加當獨立案例數。資料池、通過操作群與展示組數也分開呈現。
